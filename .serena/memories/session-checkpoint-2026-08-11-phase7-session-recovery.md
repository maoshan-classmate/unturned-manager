ADR-0005 Phase 7 终端会话恢复（2026-08-11，提交 a314f95 决策 / dd45648 后端 / 652f72b 前端 / bbe3b7b 架构文档同步）。

目标：面板重启后用户仍能看到此前开过的终端列表。

设计边界：只持久化会话元数据（编号、名称、工作目录、创建时间、最后活动时间、是否活跃）到 `<dataDir>/terminal-sessions.json`，**不录制终端输出**。早期探索版「输出录制」方案已被取代删除。

后端实现（`manager-server/src/modules/sessions/SessionManager.ts`，284 行）：
- 单 JSON 文件持久化
- 变更队列串行化，防并发写互相覆盖
- 写临时文件后改名，保证原子性
- 7 天过期自动清理
- 活动时间刷新做节流，避免高频写盘
- JSON 损坏时降级而非崩溃

接线：
- 新增端点 `GET /api/sessions`，返回活跃与已存两类会话列表
- 依赖注入容器装配，进程启动时初始化，每 24 小时清理一次，优雅关闭时把所有活跃会话标记为不活跃
- `ServerManager` 有 6 处接线：终端启动成功后保存、启动失败回滚、进程退出标记不活跃、终端输出刷新活动时间、删除实例时清理会话

前端实现：
- 新增 `useSessionManager` 钩子，加载一次会话列表
- 控制台页在实例切换器下方新增「历史终端」按钮组，只展示非当前实例的已存会话（即终端已断开的），点击提示用户点启动重新打开

测试：后端 16 个用例，前端 4 个用例。
