# 小功能走最小验证（量化版）

> 本文件是铁律数据层的一部分。**标签外**的内容是给人看的完整文档；**注入标记之间**的内容是 hook 注入到每轮对话上下文的精炼指令。量化数值由脚本从 `threshold.json` 动态读入替换占位符。

## 总原则

做功能修复/开发时，做**最小验证**——只跑必需的步骤，跑完确认无误即完成。如果删掉某些步骤后功能仍能正常运行，就删掉。如果无法判定是否属于小功能，询问用户。

## 量化标准（给人看）

| 维度 | 阈值 | 计算方式 |
|---|---|---|
| 代码文件数 | ≤ {max_files} | `git diff HEAD --name-only` 过滤后计文件数 |
| 单文件改动 | ≤ {max_lines_per_file} 行 | `git diff HEAD --numstat` 的 added + removed |

**代码文件白名单**：`{code_extensions}`

**不计入**：`.md` / `.txt` / `.json`（配置文件和文档一律排除）

**满足两条都是** → 走**最小验证**：跑 typecheck 通过即可，不跑单测/e2e。
**任一超出** → 走**完整验证**：typecheck + 单测 + e2e 三件套。

## 场景示例（给人看，不注入）

### 场景 1：修改 dialog 下拉框无法选中的问题（小功能）

- 改动：单文件 +30 行
- 错误做法：跑单元测试 + 集成测试 + e2e 全量测试 + 冒烟测试
- 正确做法：改完代码，跑 typecheck 通过即完成

### 场景 2：解决前端与后端交互的简单传值问题（小功能）

- 改动：2 个文件 +40 行
- 错误做法：跑全套测试
- 正确做法：跑 typecheck 通过即完成

### 场景 3：排查并解决控制台页面无任何输出的问题（可能不是小功能）

- 改动：跨多个文件 + 改动量大
- 错误做法：只跑 typecheck 就完事
- 正确做法：跑 typecheck + 单测 + e2e，确认控制台输出正常

## 自动检测机制（不注入）

`PostToolUse` hook（`.claude/hooks/small-feature-detect.sh`）会在每次 Edit/Write/MultiEdit 之后跑 `git diff HEAD --numstat`，自动判定累计改动是否属于小功能。属于小功能时通过 stderr + exit 2 提醒 Claude 走最小验证；超阈值时静默。
